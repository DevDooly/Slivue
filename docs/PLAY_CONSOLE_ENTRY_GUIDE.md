# Slivue Play Console 입력 가이드

기준일: **2026-11-23**. 이 문서는 소유자가 실제 Console에서 확인·입력할 준비 자료다. 계정·앱 생성, 결제, 약관 동의, 서명 등록, 신고 제출이나 게시를 자동 실행한 기록이 아니다.

## 1. 확정 값과 아직 확인할 값

| 항목 | 값·상태 |
| --- | --- |
| 앱 | Slivue의 첫 무료·무광고 Play판 준비 |
| 공개 개발자 표시 이름 | **DevDooly** — 사용자 확정. Google의 법적 신원과 별개 |
| 지원·개인정보 문의 | **vmdooly@gmail.com** — 사용자 확정. 실제 수신 확인은 별도 |
| Play 설치 식별자 | **`com.devdooly.slivue`** |
| 기존 GitHub판 | `com.devdooly.notificationedge` 유지. Play판과 별도 설치·자동 이전 없음 |
| 이전 계정 종료 | 휴면·장기 미사용이라는 사용자 확인. 정책 위반 제재로 단정하지 않음 |
| 현재 계정 | 계정 생성·본인인증 완료라는 사용자 확인. 계정 유형·생성일·추가 요구는 Console에서 확인 |
| 정책 주소 | 아래 한영 GitHub Pages 공개를 사용자 승인했으며, 실제 HTTP 200 접근과 게시 원문·앱 자산 일치를 확인 |
| 정책 내용·시행일 | **최종 승인 대기. `draft` 유지** |

| 업로드 키 | 로컬 생성·개인키 검증 완료. 이동 가능한 백업·Console 등록·서명 AAB는 별도 |
| Play 앱·서명·신고·게시 | 실제 완료 결과 미확인. 체크리스트를 대신 완료 처리하지 않음 |
| 대상 국가·연령·IARC 등급 | **소유자 선택·실제 질문 응답 필요** |

이 정책과 입력 자료는 Slivue Play판만 대상으로 한다. Thumbbridge나 DevDooly의 모든 앱을 묶은 개인정보처리방침으로 사용하지 않는다.

문의 메일의 실제 삭제·휴지통 정리 등 운영자 보관본 관리는 운영자가 직접 수행해야 한다. Google 서비스 자체의 처리·보관은 제공자 정책과 구분한다. 이 준비 작업은 메일을 자동 삭제하거나 보관 설정을 바꾸지 않는다.

## 2. 계정·등록비·신원 확인

1. 사용자가 완료했다고 확인한 계정으로 [Play Console](https://play.google.com/console/)에 로그인한다. **계정 생성과 앱 생성은 다르다.** 새 계정을 다시 만들거나 등록비를 중복 결제하지 말고 현재 대시보드의 상태를 확인한다.
2. 계정 유형·생성일·국가, 공개 표시 이름 `DevDooly`, 연락처 확인과 추가 검증 항목을 읽는다. 개인 운영이라면 실제 개인 신원을 사용한다. 허위 조직·신원으로 요구사항을 피하지 않는다.
3. 계정 생성·본인인증은 사용자 확인 완료지만 등록비 영수증·실제 결제액·결제 처리 상태는 이 작업에서 열람하지 않았다. 공식 가입 안내는 일회성 US$25 등록비를 설명한다. 실제 결제·통화·세금·등록 완료는 본인의 Console/영수증으로 확인한다. [공식 가입 안내](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)
4. 개발자 배포 계약·수출 관련 약관 등 법적 동의는 소유자가 내용을 읽고 직접 선택한다. 신분증·개인 주소·결제 정보·비밀번호·OTP는 Git·이슈·Slack·이 문서에 남기지 않는다.
5. 휴면 종료와 정책 제재는 구분한다. 기존 계정 상태가 사용자 확인과 다르게 표시되거나 새 계정 등록 제한이 나오면 Google 지원에서 해당 사유를 확인한다. 종료 사유를 바꾸거나 연관 관계를 숨겨 우회하지 않는다. [휴면 계정 공식 안내](https://support.google.com/googleplay/android-developer/answer/11605267?hl=en)

## 3. 새 앱과 설치 식별자

1. Console의 **앱 만들기**에서 Slivue 앱을 준비한다. 기본 언어는 한국어를 선택하는 구성을 권고하며, 영어 등록정보는 뒤에서 추가한다. 앱/게임은 실제 제품인 앱, 무료/유료는 첫 무료 출시 계획에 맞춰 소유자가 확인한다.
2. 앱 표시 제목·소개는 다음 원문을 사용한다. 글자 수와 실제 기능의 일치는 원문·미리보기로 검증한다.

| 등록정보 | 한국어 | 영어 |
| --- | --- | --- |
| 이름 | [한국어 이름](google-play/listings/ko-KR/title.txt) | [영어 이름](google-play/listings/en-US/title.txt) |
| 짧은 설명 | [한국어 짧은 설명](google-play/listings/ko-KR/short_description.txt) | [영어 짧은 설명](google-play/listings/en-US/short_description.txt) |
| 상세 설명 | [한국어 상세 설명](google-play/listings/ko-KR/full_description.txt) | [영어 상세 설명](google-play/listings/en-US/full_description.txt) |

3. 앱 생성 화면에 패키지 입력란이 없더라도 임의 필드에 넣지 않는다. 첫 AAB의 manifest에서 설치 식별자가 연결되므로 **`com.devdooly.slivue`인 Play AAB만** 사용한다. `com.devdooly.notificationedge` APK나 미서명 후보를 올리지 않는다.
4. 패키지는 영구적인 식별자이며 사용·재사용 제한을 Console에서 확인한다. 같은 이름의 다른 앱과 혼동하지 말고 첫 업로드 후 표시된 식별자를 대조한다. [앱 생성·패키지 공식 안내](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en)

## 5. 앱 콘텐츠 입력 준비

Console 메뉴 명칭은 변경될 수 있으므로 실제 화면의 **앱 콘텐츠**와 대시보드 요구사항을 기준으로 진행한다. 아래는 최종 신고를 대신하는 자동 답안이 아니다.

| 항목 | Slivue 준비 기준 | 제출 전 확인 |
| --- | --- | --- |
| 광고 | 첫 Play판에는 광고 SDK·광고 표시가 없는 구성 | 최종 산출물·화면을 확인한 뒤 답함. 향후 광고 추가 시 갱신 |
| 앱 접근 | 별도 Slivue 로그인·회원가입·멤버십은 없음 | 알림 접근·오버레이 등 필요한 OS 권한과 합성 알림 재현 방법을 안내. 없는 시연 도구를 있다고 쓰지 않음 |
| 대상 연령·콘텐츠 등급 | 미정 | 실제 사용 대상·콘텐츠에 맞게 소유자가 질문에 답함. 규칙을 피하려 연령이나 등급을 추측하지 않음 |
| 배포 국가·지역 | 미정 | 운영·지원 가능 범위를 소유자가 선택. 영어 지원을 전 세계 공개 결정으로 해석하지 않음 |
| Data safety | 아래 잠정 검토표와 최종 동작 대조 | 소유자 검토 없이 “수집·공유 없음” 일괄 선택 금지 |
| FGS·권한 | `specialUse`와 실제 알림 접근·오버레이 기능 설명 | 실제 manifest·기능·시연 영상·사용자 중지 동작과 일치해야 함 |

### Data safety 잠정 검토표

최종 Play AAB·전이 SDK·실제 전송·삭제/백업 증거를 확인한 뒤 신고한다. [공식 신고 정의](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

| 정보·처리 | 현재 설계의 검토 방향 | 오해하지 않을 점 |
| --- | --- | --- |
| 알림 제목·본문·발신자·앱·수신 시각 | 기기 내 표시·필터·라이팅 처리, 메모리 이력 | 민감 접근 고지는 필요하며 로컬 처리만 확인되어야 기기 밖 수집과 구분 가능 |
| 빠른 답장 | 사용자가 누르면 원래 메시지 앱에 전달 | 다른 앱 전달과 사용자 요청 예외를 조건별로 검토. 무조건 공유 없음으로 단정하지 않음 |
| 발견 앱·차단어·환경 설정·폰트 | 앱 내부 저장·Play 백업 제외 설계 | 실제 삭제·전송·OEM 이전 결과를 추가 확인 |
| IP·식별자·오류·사용량 | 자체 네트워크·광고·분석 SDK 제외 설계 | 인터넷 권한 부재만으로 모든 외부 서비스의 동작까지 확정하지 않음 |
| 정책·스토어 링크와 지원 문의 | 사용자가 외부 브라우저·스토어·메일 서비스를 이용 | 실제 문의 처리·보관·삭제 및 외부 제공자 범위와 정책 문구를 대조 |

자세한 증거와 잠정 답안은 [제출 점검표 6절](GOOGLE_PLAY_SUBMISSION_CHECKLIST.md#6-data-safety-잠정-답안과-증거)을 따른다. 회원가입 기능이 없는 Slivue에 가상의 회원탈퇴 웹페이지를 만들지 않으며, 향후 계정 기능이 생기면 다시 검토한다.

### FGS 설명에 사용할 한국어 초안

> Slivue는 사용자가 켠 화면 가장자리 핸들과 새 알림의 엣지 라이팅을 다른 앱 사용 중에도 제공하기 위해 `specialUse` 포그라운드 서비스를 사용합니다. 핸들이 중단되면 사용자가 설정한 가장자리 제스처를 즉시 받을 수 없고, 라이팅이 지연되면 요청한 새 알림 강조가 제때 동작하지 않습니다. 사용자가 설정에서 시작하며 실행 상태 알림과 설정에서 전체 중지할 수 있습니다. 중지·동의 철회·알림 접근 해제 상태를 부팅이나 외부 명령으로 우회하지 않습니다.

알림 접근 설명에는 “앱 내부 고지에 동의하고 Android 알림 접근을 허용한 경우 다른 앱의 제목·내용·발신자·대화·답장 동작을 읽어 패널과 필터에 사용하며, 직접 입력한 답장은 원래 앱에 전달한다”는 실제 범위를 명시한다. 오버레이 권한과 알림 보내기 권한은 각각 핸들/라이팅 표시, Slivue 서비스 상태 알림을 위한 별도 항목이다.

`specialUse`가 승인된다고 가정하거나 미디어 재생·위치 추적·전체 화면 인텐트 유형으로 기능을 잘못 설명하지 않는다. 앱 콘텐츠에서 기능·지연/중단 영향·사용자가 켜는 과정을 보여 주는 영상 등 실제 요구 자료를 제출한다. [FGS 신고 안내](https://support.google.com/googleplay/android-developer/answer/13392821?hl=en)

## 6. 심사 시연 영상과 재현 안내

1. 최종 제출할 Play 빌드의 버전·설치 식별자와 시험 기기/Android 버전을 보여 준다.
2. 한영 개인정보 안내·고지에서 나중에/거절을 선택하면 알림 처리가 시작되지 않는 흐름을 보여 준다.
3. 명시적으로 동의하고 OS 알림 접근·오버레이를 허용한 뒤 앱에 복귀한다. 서비스 상태 알림 권한은 별도 항목임을 보여 준다.
4. 핸들과 라이팅을 사용자가 켜고, 합성 알림으로 패널·앱/키워드 필터를 시연한다. 실제 개인 대화를 촬영하지 않는다.
5. 빠른 답장은 `RemoteInput`을 지원하는 시험 알림을 준비해 원래 앱으로 전달되는 동작을 보여 준다. 전송 대상 없는 미리보기 알림을 실제 전송 성공처럼 설명하지 않는다.
6. 설정 또는 상태 알림에서 전체 중지하고 메모리 이력·핸들·라이팅이 중단되는 것을 보여 준다. 재개와 OS 권한 철회도 시연한다.
7. 키보드 입력·뒤로가기·한 줄 헤더·큰 글씨에서 필요한 버튼이 가려지지 않는지 확인한다.
8. 심사자가 로그인 없이 볼 수 있는 영상 주소와 재현 방법을 준비한다. 영상 업로드·최종 공개는 별도 작업이며 이 문서로 완료 처리하지 않는다.

## 7. Play 서명과 내부 테스트

1. [서명 전략](GOOGLE_PLAY_SIGNING_AND_MONETIZATION.md)에서 로컬 생성·검증을 완료한 독립 업로드 키의 공개 지문을 확인하고 이동 가능한 백업·복구를 별도로 준비한다. 키 파일이나 암호를 Console 설명란에 붙이지 않는다. 요청될 때만 해당 공개 인증서를 사용한다.
2. 소유자가 Play App Signing의 앱 서명키 방식·약관을 확인한다. 업로드 키와 사용자가 설치하는 APK의 앱 서명키를 구분하고 기존 GitHub 키를 새 Play 키로 재사용하지 않는다. [앱 서명 공식 안내](https://support.google.com/googleplay/android-developer/answer/9842756?hl=en)
3. 정책 최종 승인과 운영 메타데이터·키 설정 후 `verifyPlaySubmissionReady`, `preparePlaySubmission`을 통과한 **이번 성공 폴더의 서명 AAB**를 사용한다. 과거 후보나 `latest-attempt.json`의 `not_ready` 결과를 제출하지 않는다.
4. 내부 테스트 트랙에 올려 실제 패키지·업로드 인증서·Play 앱 서명 인증서·신규 설치·다음 후보 업데이트를 검증한다. 내부 앱 공유의 별도 테스트 서명과 혼동하지 않는다.
5. Pre-launch report의 충돌·ANR·접근성·16KB/기기 문제와 실제 권한·중지·뒤로가기 흐름을 확인한다. 로컬·GitHub CI 통과는 Play 설치 검증을 대신하지 않는다.

이 문서와 로컬 서명 후보 생성은 실제 Console 서명 등록·업로드 완료 증거가 아니다.

## 8. 해당 신규 개인 계정의 비공개 테스트와 출시

계정 유형·생성일을 Console에서 확인한다. **2023-11-13 이후 생성된 개인 계정에 해당하면 최소 12명이 직전 연속 14일간 비공개 테스트에 참여한 상태**로 프로덕션 액세스를 신청한다. 실제 사용·피드백·수정 기록을 남기고, 이탈·재참여는 연속 기간에 영향을 줄 수 있다. 내부 테스트·에뮬레이터 12대·단순 14일 경과로 대신하지 않는다. 조건 충족은 자동 승인이 아니다. [공식 테스트 요구](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)

개인 계정에 추가되는 실제 Android 기기 확인 등 현재 대시보드의 요구도 소유자가 수행한다. 기존 계정의 생성일이나 폐쇄 전 기록이 새 계정의 면제를 보장한다고 가정하지 않는다.

계정·앱·정책·서명·등급/국가·FGS/Data safety·테스트·심사 자료가 준비된 후 소유자가 실제 Console에서 최종 제출·게시 여부를 확인한다. 광고·계정·동기화 등 기능을 나중에 추가하면 배포 전에 정책과 신고를 재검토한다.
